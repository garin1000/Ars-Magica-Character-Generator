# Full-codebase audit — August 2026

A whole-repository review run after Milestone 6 closed, covering `crates/`, `ui/src/`,
`ui/e2e/`, `rules/core/`, `rules/i18n/`, `locales/` and the root docs and CI. The verbatim
rulebooks under `rules/source/**` were consulted to verify rules and citations, never
reviewed as subjects.

Nine independent reviewers produced **57 findings** (5 CRITICAL, 12 HIGH, 26 MEDIUM,
15 LOW) across architecture, code quality, security, accessibility and test coverage. All
were worked through; what remains open is listed at the end.

## What changed

### Security and untrusted input

- **Crafted-save denial of service.** `xp_allocation`'s max-flow solver allocated a dense
  n×n matrix where n scaled with the entries in the loaded file, so a `.armc` with tens of
  thousands of `ability_scores` forced a multi-gigabyte allocation and aborted the process
  on a plain File → Open. Saves are realistically attacker-supplied (downloaded from a
  forum, handed over by a troupe-mate). Bounded by `MAX_XP_SOLVE_NODES` plus a
  validation-time rejection that names the offending counts, so the user gets a normal error
  and a live app. The bound constrains an entity's own selections, never catalogue size —
  catalogue growth must stay a data-only change.

  > **Correction (round 2).** Round 1 described this as bounded "in two layers", with the
  > validation check said to cover `xp_allocation`'s "only call site" — a claim written into
  > a code comment in `validation/magus.rs`. There are in fact **four** call sites, and three
  > were unguarded: `export/sections.rs`, `arm-app`'s `ruleset_io.rs::xp_fields` (which feeds
  > the `effective_scores` command), and `effective/xp.rs::restricted_xp_pools`. Because the
  > frontend fires `validateEntity`, `effectiveScores` and `derivedTotals` together via
  > `Promise.all`, a crafted save still reached the solver's `assert!` and panicked on a
  > plain File → Open — and `Promise.all` discards the fulfilled sibling, so the graceful
  > validation error never surfaced. Two round-2 reviewers found this independently. The
  > lesson recorded: a guard that depends on every caller remembering to check is not a
  > guard, and the orchestrator accepted the "only call site" claim without verifying the
  > reachability premise under it.
- **`Entity.aura` overflow.** An unvalidated `i32` that wrapped in release and panicked in
  debug. Bounded to `AURA_MODIFIER_MIN..=AURA_MODIFIER_MAX` (−50..=10, derived from the
  1–10 rating scale and the Realm Interaction Table's ×5 worst case), and every total that
  sums it now routes through `derived::saturating_i32_sum`.
- **Content-Security-Policy.** `tauri.conf.json` shipped `"csp": null`. Now a strict
  policy. Defence in depth rather than a live hole — there is no `{@html}` or `innerHTML`
  anywhere in the components.
- **e2e seams no longer ship.** `ARM_E2E_FILE` / `ARM_E2E_EXPORT_FILE` let an environment
  variable redirect save/load away from the native dialog, compiled unconditionally into
  release builds. Now behind an `e2e-testing` Cargo feature, off by default; the e2e build
  passes `--features e2e-testing`.
- **CI supply chain.** `release.yml` pinned third-party actions by mutable tag while
  holding `contents: write`. All six now pinned to commit SHAs, and `contents: write` is
  narrowed to the single job that needs it. `dtolnay/rust-toolchain` publishes no version
  tags, so it is pinned to a branch tip and **needs periodic re-verification**.
- **`window.close()` bypassed the unsaved-changes guard.** WebKitGTK and WebView2 wire JS
  `window.close()` straight to window destruction without raising `CloseRequested`. A
  `js_init_script` now shadows it onto a `request_close` command that routes through the
  existing guard.

### The unsaved-changes guard (a mandatory product behavior)

Four reviewers hit this surface independently. Its IPC mirror had **zero test coverage**:
the frontend suite was SSR-only, so no `$effect` had ever been executed by any test, and a
regression breaking the guard would have passed everything. Fixed by adding a client test
environment (below) and five assertions in `ui/src/App.client.test.ts`, including that
undoing an edit re-mirrors clean — the snapshot-compare property a naive boolean would
fail. `DiscardPrompt` also gained focus management, Escape-to-cancel and app inertness.

> **Round 2 additions.** Three of round 1's fixes on this surface shipped untested, and two
> were incomplete. The `request_close` command that closes the JS `window.close()` bypass had
> no coverage at any layer; the `DiscardPrompt`/`StartScreen` focus-management `$effect`s had
> none either — the very class the new client vitest project was added to make testable.
> `DiscardPrompt` never restored focus to the control that opened it, and
> `ValidationPanel`'s severity fix added an sr-only prefix but left sighted colourblind
> users with colour as the only channel. All addressed in round 2.

### Accessibility

`SourcePicker` — shared by the Virtues & Flaws, Abilities, Spells and Equipment tabs —
used native `disabled`, which removes an element from the tab order, so the tooltip
explaining *why* an item was blocked could never be reached by keyboard or screen reader.
Now `aria-disabled` with a guarded click handler. Remove buttons across several tabs had no
accessible name (one had none at all); the validation panel conveyed severity by colour
alone and had no `aria-live`.

### Engine logic duplicated in TypeScript

`characteristicPointsUsed` reimplemented the engine's `CharacteristicRules::total_cost`
(found independently by three reviewers), and `abilityXpSpent`/`artXpSpent` were dead code
that computed *wrong* figures — ignoring Affinity and floor reductions — sitting beside a
function whose own doc comment explained why that was the mistake to avoid.
`abilityXpSpent`/`artXpSpent` were removed. The ritual minimum spell level, hardcoded in
`SpellTab.svelte`, is now surfaced as `Ruleset.ritual_min_level`.

> **Correction (round 2).** An earlier version of this section, and the `e654de5` commit
> message, stated that `characteristicPointsUsed` had also been removed. **It had not.** It
> remained defined in `ui/src/lib/derive.ts` and live-called from
> `CharacteristicPicker.svelte`; only a comment acknowledging the duplication was added. The
> round-1 report claimed the removal, and the orchestrator's verifying `grep` ran against a
> path that did not resolve (shell working directory had drifted into `ui/`), returned empty,
> and was read as "absent". Two round-2 reviewers found it independently. A third duplication
> — `spellMasteryXpSpent`, which additionally handles only one Affinity ratio — was found in
> the same round. See "Round 2" below.

### Export

`export.rs` degraded a missing Fluent key to the raw slug, which CLAUDE.md forbids
("rendering the slug itself is the same violation as hardcoding a string"). It now fails
loudly, collecting **every** missing key in one pass rather than the first, surfaced as
`AppError::Export` with an `error-export` message in both locales. Byte-determinism and
the golden fixture are unchanged.

### Rules provenance

- `RULES.md` cited a deleted `src/validation.rs` at **26** sites (the review found 7).
- **~470** `// Source:` citations used shorthand book names (`Core Rules.md`, `Core:NNNN`,
  `RoP:Magic`) matching no real file. All normalised to the real basenames in
  `rules/source/en/`.
- **Four wrong line ranges** were found and corrected, each hiding behind a shorthand
  citation and each caught only by opening the source file:
  - `characteristics.rs` cited Poor (Characteristic)'s −5 floor where it meant the
    point-buy table's −3 row.
  - `types.rs` confidence cited a section heading (`:2521`) rather than the rule (`:2524`).
  - The non-Ritual level-50 ceiling was cited at `:12283` (a Year-duration restriction) in
    three places; an intermediate correction to `:12291` was also wrong (a discretionary
    design-rationale sentence). The rule is at **`:12285`**.
  No citation's rule was unlocatable, so there were no rules-from-memory violations.

Each split keeps the original file as the parent module declaring its children, so `lib.rs`
and every public path are untouched. `derived.rs` additionally needs `pub use` re-exports
because its items are free functions rather than inherent methods. The whole test suite
passed throughout with **no test changed** beyond two import lines and a handful of
documented visibility widenings.

`Ruleset::from_sources` went from 267 lines to a ~15-line pipeline, and the "source line
range is valid" check that was copy-pasted across nine integrity sites is now one helper —
with each call site passing its own subject string, so all nine error messages stay
byte-identical.

## Two reported findings were not defects

Worth recording, because both looked convincing:

- A CRITICAL claimed `groupSpellsByTechniqueForm` joined a map key with a NUL byte while
  the defensive branch split on a space, yielding `undefined`. **Both sides used the same
  NUL** — the grouping was correct and the proposed "change it to a space" fix would have
  broken any id containing a space. What was real was only that a raw NUL made the file
  invisible to `grep` (`-I` is hardcoded in this environment's shim) and made `file` report
  `data`; writing the separator as the escape `'\0'` fixed that with identical runtime
  behavior.
- A MEDIUM claimed `CloseGuardState::confirmed` was a one-way latch. It is cleared in
  `report_dirty_state` on every dirty report from the frontend. No change was needed.

## Still open

- **`AppStore` (2065 lines) and `ruleset.rs` (5022 lines) remain large.** Both are improved,
  not resolved. The residual bulk in each is a single coherent axis (entity-field CRUD; the
  `Ruleset` types plus their test module), so further splitting was judged churn rather
  than clarity. Revisit if either grows.
- **Bare `:NNNN` continuation citations** (a line number with the book named earlier in the
  same doc comment) are pervasive across 16 files. Left as an established local convention;
  they read unambiguously in context but do not satisfy the letter of the provenance rule.
- **`dtolnay/rust-toolchain` is pinned to a branch tip**, not a tag — it publishes none.
  Re-verify periodically.
- **27 npm advisories (1 critical, 22 high) are dev-only.** `npm audit --omit=dev` reports
  **0**, so nothing reaches the shipped product. The round-1 security review checked
  dependency pinning but never ran an advisory scan, so this class was missed entirely.
- `validate_effect_refs` stays at 147 lines: one exhaustive enum match with no repeated
  logic, where splitting would obscure rather than clarify.

## Operational notes for the next audit

- **Never run the e2e suite while anything else compiles.** Two runs produced false
  failures from build races on the shared `target/` directory — one fell back to a stale
  binary, one had the binary overwritten mid-run by a build lacking `--features
  e2e-testing` (proved by `strings` showing no `ARM_E2E_FILE`). Both looked like real
  defects.
- **A NUL byte in a source file defeats `grep` silently** — and defeats `git diff` on that
  file too, so a diff pipeline through `grep` drops everything. `file` reporting `data`
  rather than `text` is the tell.
- **`cd` persists between shell calls here.** After a `cd ui` for the frontend gate, later
  repo-relative paths silently resolve under `ui/`, which makes `git diff -- crates/…`
  return empty and greps report a missing file.
